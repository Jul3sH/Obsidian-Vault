# Bias Check

## Purpose

- Julian's documented biases live as mm cards, indexed by trigger situation in `wiki/performance/biases-index.md`.
- This skill is the dispatcher that makes the index practical: when a conversation enters a situation where a documented bias tends to fire, it checks the index and raises the matching card at the moment it can still change the outcome.
- Built 19 Sep 2026 as part of [[bias-history-review]]; without this skill the index is a reference library, not a guardrail.

## Procedure

1. **Read the index.** Open `wiki/performance/biases-index.md` and scan the "Fires when" column against the current situation.
2. **Match narrowly.** Identify which rows genuinely match what is happening now. Most situations match one or two rows; matching four or more means the match is too loose - pick the ones whose "fires when" wording actually describes the moment.
3. **Check precedence.** Two biases have dedicated skills that take over their specific patterns:
   - Reopening a LOCKED decision → hand to `commitment-guard` (run the reopen test), do not duplicate it here.
   - Warming to an option by feel/image → `decision-visualisation-check` owns the both-images intervention.
   If either fires, this skill stays silent on that row.
4. **Raise it briefly.** One short paragraph, not a lecture: name the bias, one line on why this moment matches, the card's one-liner, and the single most relevant guideline. Link the card. Then continue with the work - this is a checkpoint, not a blocker.
5. **Julian overrules freely.** If he says the bias does not apply here, accept it and continue. Log nothing. The skill's job is to make the check happen, not to win it.

## Rules

- Raise at most two biases per moment. If more seem to apply, name the strongest match only and mention the index exists.
- Never fire twice on the same bias in the same piece of work unless the situation has materially changed.
- This skill reads the index fresh each time - never from memory - so new rows are picked up automatically.

## Maintenance

- When a new row is added to `biases-index.md`, check that its "Fires when" situation is covered by one of the trigger situations in this skill's description; if not, widen the description in the same operation (this rule is also written into `documentation-conventions.md` Part 1).
- Keep this skill and the index in lockstep.
- Trigger list widened from seven to twelve situations on 19 Sep 2026 after the artefact-level adversarial review found five index rows uncovered: fear-disguise, certainty-spike, sunk-cost beyond financial models, confirmation-amplification at review time, and payoff-vs-prestige on learning choices.
- Situation 8 widened 22 Sep 2026 to cover changes to existing systems, alongside the new forgotten-system-bias index row.
