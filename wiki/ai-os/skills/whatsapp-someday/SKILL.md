# WhatsApp Someday Import

- Julian keeps a "Someday" self-chat in WhatsApp: personal reminders + links shared to himself.
- He exports it (Settings > Export Chat > Without Media) and drops the `.txt` into a Dropbox folder that syncs locally.
- This skill turns a new export into wiki content, using the method established manually on 2026-08-15 (see `wiki/ai-os/logs/log-2026-Q3.md`, 2026-08-15 Compile entries).
- **Manual invocation only** (`/whatsapp-someday`). A weekly automation was built and discontinued the same day (2026-08-15); record: `wiki/ai-os/system-design/claude/local-automation.md`.
- **Drop folder:** `~/Library/CloudStorage/Dropbox/5-Performance/Whatsapp someday/`. Any `.txt` directly in that folder (not in its `_processed/` subfolder) is new; filenames don't matter.

## Step 0 - Find new exports

```bash
ls "$HOME/Library/CloudStorage/Dropbox/5-Performance/Whatsapp someday/"*.txt 2>/dev/null
```

- No match: tell Julian there's nothing new and stop.
- Multiple files: process each in turn, oldest first (by mtime).

## Step 1 - Parse the export

- Format: `[D/M/YYYY, H:MM:SS AM/PM] Sender: message`. Attachments appear as `<attached: filename>` placeholders with no content.
- Split every message into exactly one of three buckets:
  1. **Bare share link** - entire body is a single URL (Instagram, YouTube, LinkedIn, other). The overwhelming majority.
  2. **Substantive text** - anything else: notes, reflections, drafts, questions. A comment + link mix = comment as text, link separately.
  3. **Attachment placeholder** - drop without processing. If the filename suggests real value (e.g. a named PDF guide), note it in the run summary so Julian can supply the file; don't chase it.
- Also drop without processing:
  - Stale logistics for a dated one-off event already passed.
  - Claude Code's own prior session output pasted in as a note-to-self.

## Step 2 - Route substantive text

- Search the wiki for an existing, **clearly-matching** home first: an article whose subject the note is unambiguously about (a family member's health file, a named behavioural-pattern article, a project status doc), not a vague thematic match. Precedents (2026-08-15): Father's Day note → [[dad-health-discussions]]; 16 Jul self-notes → [[commitment-avoidance]].
- **Match found:** append there, dated, in that file's existing style. Update its "last updated" line if it has one.
- **No clear match:** drop into `raw/brain-dump.md` **Personal** section as a normal capture-inbox item, in its `| Item | Note |` table style. Never create a new wiki file (AGENTS.md: names agreed with Julian first).

## Step 3 - Fetch and categorise share links

- Fetch real content before writing any description; never invent one from the URL slug.
- **Instagram** (`/reel/`, `/p/`): plain fetch is bot-walled. Append `embed/captioned/` to the path (e.g. `https://www.instagram.com/reel/XXXXX/embed/captioned/`) - returns caption, handle, stats without login. Verified 2026-08-15, ~85% success across ~140 links.
- **YouTube** (`youtu.be`, `/shorts/`, `/post/`): follow redirect to the watch page and fetch it; oEmbed (`youtube.com/oembed?url=...`) is a faster title-only fallback.
- **LinkedIn posts:** fetch directly; confirm against the fetched page rather than relying on the slug.
- Fails after one retry (login wall, deleted, private): put on a dropped/unavailable list, no forced description.
- Classify each described item into one of `raw/brain-dump.md`'s four workstreams:
  - **Career** - job search, hiring, interviews, career strategy
  - **Performance** - self-management, mindset, communication, productivity, leadership, business/founder advice
  - **Wiki / AI OS** - Claude/Claude Code, AI agents, tools, skills, prompting, anything feeding this vault's AI-OS tooling
  - **Personal** - everything else (fitness, hobbies, relationships, home, lifestyle, entertainment). Usually the largest.

## Step 4 - Write to the wiki

- Append a dated subsection to each affected workstream in `raw/brain-dump.md`:

```
### WhatsApp Someday import (<today's date>)

| Item | Note |
|------|------|
| ... |

**Source links:**
- ...
```

- One-line descriptions only (the file treats verbosity as a defect).
- Collapse near-duplicate saves of the same account/theme into one row with a count.
- Update the file's frontmatter `updated:` date.
- List any failures under `**Dropped as unavailable (N):**` so nothing silently vanishes.

## Step 5 - Close out the file

1. `mkdir -p` `_processed/` inside the Dropbox folder if needed; move the processed `.txt` there (mirrors the vault's `raw/` → `raw/_processed/` convention).
2. Append a row to `wiki/ai-os/logs/raw-manifest.md`: source filename, wiki destination(s), date.
3. Append a `Compile` row to the current quarter's ops log (check `CLAUDE.md` for the pointer): notes routed and where, links per workstream, drops.
4. Short chat summary to Julian (links per workstream, notes routed, drops) - manual run, so this replaces any notification.
