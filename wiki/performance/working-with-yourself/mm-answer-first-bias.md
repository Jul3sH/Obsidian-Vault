# MM: Answer-First Bias

This card names the bias of writing the persuasive case before the adversarial review has run - locking the conclusion in before the evidence has been hostile-tested. Documented as bias #5 in the [[commitment-lock-protocol]] register: the UK-move persuasion document was written before the adversarial review that later corrected its numbers.

**One-liner:** A case written before the review is advocacy, not analysis.

**Reach for it when:** drafting any document that argues for a conclusion - an anchor doc, a proposal, a recommendation - and the adversarial pass has not yet run.

## Key Takeaways

- Sequencing is the whole bias: the same document written after review is analysis; written before, it is advocacy that review then struggles to dislodge.
- A persuasion doc built on pre-review numbers keeps its rhetorical shape even after the numbers are corrected - the frame survives the facts.
- The order of operations is checkable, which makes this one of the easiest biases to catch: just ask what ran first.

## Principles

- **Conclusions are written down after hostile review, never before.**
- **A document's persuasiveness is independent of its correctness.**
- **The frame set first wins ties - so set it last.**

## Guidelines

- Anchor documents and outbound cases are written only from post-review numbers ([[commitment-lock-protocol]] division of labour).
- Brief the adversarial reviewer to check sequencing: was persuasion drafted before review? Did the numbers move one way?
- If a case document already exists pre-review, treat it as a hypothesis list, not a draft to polish.

## Limitations

- Working notes and exploratory drafts are fine pre-review - the rule bites when a document is written to persuade (yourself or others).
