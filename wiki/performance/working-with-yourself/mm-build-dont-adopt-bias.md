# MM: Build-Don't-Adopt Bias

This card names the bias of getting the reward from designing a system and abandoning it before adoption. The [[bias-history-review]] scan returned "uncertain"; the subsequent ruling was real-but-narrower: one unambiguous self-diagnosed instance (the Jira sprint system, 22 Jul 2026), while a supposed second instance - the folder-structure convention - was in fact adopted into AGENTS.md as a standing rule. The bias is real; it is also already being countered by the systems-register rule.

**One-liner:** Building the system is the dopamine; adoption is the work - no build without a forcing function.

**Reach for it when:** designing any new system, process, register, log, or structure - especially when the design feels energising and the imagined future use is vivid.

## Key Takeaways

- The confirmed shape: "I spent all this time creating a new Jira system using sprints... and then I just stopped using it... we love creating the systems but then don't have the discipline to use them" (22 Jul 2026, Julian's own diagnosis).
- The bias acts at build time, not use time: the moment of enthusiasm is when the adoption question must be forced.
- Counter-evidence matters: systems with forcing functions built in (the folder convention, enforced by index rules) did get adopted. The bias is beatable by design.

## Principles

- **The energy of designing is not evidence the system will be used.**
- **A system without a forcing function is a decoration.**
- **Reuse beats build:** extending an adopted system inherits its adoption; a new system starts at zero.

## Guidelines

- Before building: search the existing estate first (the AGENTS.md Reuse Before Build rule).
- Every new system gets a [[systems-register]] row with a named adoption forcing-function, in the same operation as the build (`feedback-build-dont-adopt` memory).
- Prefer wiring the new thing into an existing ceremony or hook over relying on remembering to use it.

## Limitations

- Deliberate prototypes and experiments may be built to be discarded - say so at build time, then discarding is the plan, not the bias.
